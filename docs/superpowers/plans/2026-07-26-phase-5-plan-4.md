# Phase 5 Plan 4 — Reinforce, Recall & Surfacing — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the contextual mnemonic co-creation loop — a hook can be tested, reinforced, deepened and used at the moment of need — while unblocking the Plan 2 API deploy and fixing the three-month-old daily push notification failure.

**Architecture:** Deploy-first (approach A). Two deprecated no-op stubs sever the "new API breaks old mobile" constraint, which lets the Plan 2 API deploy immediately and `phase-5-cocreation-ui` merge to `main` — restoring a shippable `main` before any feature work begins. Feature work then proceeds incrementally on green `main`. Server-side push fixes ride the step-1 deploy; client-side push fixes ride the final EAS build.

**Tech Stack:** Fastify + drizzle + postgres-js (API) · React Native / Expo Router + zustand (mobile) · vitest (API, shared) · jest (mobile) · `expo-server-sdk` (push) · AWS App Runner + EventBridge + Lambda

## Verification strategy (decided 2026-07-27)

**No dev-client / on-device verification during Tasks 4–18. Device testing is batched into a single TestFlight cut at Task 19.**

Why: an attempt to stand up a development build burned substantial time for zero verification — the simulator picker offered only simulators (all physical devices were offline), `xcodebuild` failed with error 65 (no Apple ID in Xcode), and `eas build` tried to disable Apple sign-in on the production bundle. None of that friction bought a single confirmed behaviour.

It was also unnecessary. Only four things genuinely require a device — the **location grant path** (real GPS + reverse geocoding), the **on-device Apple Foundation Models tier**, **UI layout/feel**, and **push delivery** — and every one of them needs a *build* regardless. Task 19 already exists as exactly that batch point; the dev-client detour was off-plan.

So for Tasks 4–18, "verified" means:

- **Shared logic** → real tests (`packages/shared`, vitest)
- **API** → integration tests (`apps/api`, vitest) — rebuild the test DB first, per [`local-test-db.md`](../../local-test-db.md), or stale state inflates failures by ~5
- **Mobile logic** → pure reducer tests (`apps/mobile`, jest — note there is **no React renderer** in this project)
- **Mobile UI** → `pnpm --filter @kanji-learn/mobile typecheck` at 0 errors, and nothing more. UI correctness is deferred to Task 19 by design.

**One mid-plan exception:** Task 5a needs a real API deploy for the push fixes to reach production. Server-side only — no build, no device.

Accepted trade-off: defects in UI surface at Task 19 rather than when written. Judged worthwhile because the previous walkthrough's findings were layout and copy issues that only a real build surfaces anyway.

## Global Constraints

- **Mobile typecheck must be 0 errors before ANY EAS build.** `pnpm --filter @kanji-learn/mobile typecheck`. This rule exists because a build was once cut on a broken commit (B139 saga).
- **Never hand-bump `ios.buildNumber`.** `autoIncrement: true` bumps it on EAS; commit the auto-written `app.json` after each cut.
- **API response envelope is `{ ok: true, data }`.** The mobile `ApiClient` throws on `!json.ok`. A bare `{ data }` makes every consumer invisible.
- **Copy discipline for deepen:** never "rebuild", "start over", "discard", "replace". Additive language only — "go deeper", "add another thread", "what does this connect to?"
- **Never `cat`/`grep` files known to contain secrets** (`.env`, `credentials.json`, `*.key`). Scope AWS `--query` to key names only.
- **`apps/mobile/ios/` is gitignored** — EAS prebuilds on the builder. Only `app.json` / `eas.json` / env vars reach EAS.
- **Verify every Edit actually applied.** Watch for "File has not been read yet" — a silently-failed edit once shipped a TS2305 regression.
- **Test locations:** shared → `packages/shared/src/**/*.test.ts` · API → `apps/api/test/**/*.test.ts` (vitest `include: ['test/**/*.test.ts']`) · mobile → `apps/mobile/test/**`.
- **API integration-test conventions (verified 2026-07-26).** `apps/api/test/helpers/` contains exactly one file: `test-app.ts`. There is **no** `helpers/auth.ts` and **no** `helpers/db.ts`. Authenticate with a bare header — `headers: { 'x-test-user-id': '<uuid>' }` — and obtain the db handle from `buildTestApp()`. Copy setup/teardown from `apps/api/test/integration/buddy-nudges-route.test.ts`.
- **Migrate before you deploy.** `scripts/deploy-api.sh` builds from the monorepo root, so the image carries `packages/db/src/schema.ts`; drizzle relational queries emit an explicit column list, and hot paths like `apps/api/src/routes/user.ts:10` select no subset. Deploying a schema ahead of its migration 500s every profile fetch. Additive migrations are invisible to the running API, so they always go first.

### Task 4: Poll Expo receipts — make delivery failures visible

**Defect C.** `sendToUserTokens` returns `sent: tickets.length`. Tickets are Expo's *synchronous acceptance*, not delivery. Real outcomes (`DeviceNotRegistered`, `MessageRateExceeded`, `InvalidCredentials`) appear only in receipts, which nothing polls. This is why two real bugs stayed invisible for three months.

**Files:**
- Modify: `apps/api/src/services/notification.service.ts:389-427` (`sendToUserTokens`)
- Test: `apps/api/test/integration/push-receipts.test.ts` (create)

**Interfaces:**
- Consumes: `expo.sendPushNotificationsAsync`, `expo.getPushNotificationReceiptsAsync` from `expo-server-sdk`.
- Produces: `sendToUserTokens(userId, message) → { sent: number; pruned: number; accepted: number }` — `accepted` is ticket count (old `sent` semantics), `sent` now means receipts confirmed OK.

```ts
  async sendToUserTokens(
    userId: string,
    message: Omit<ExpoPushMessage, 'to'>,
  ): Promise<{ sent: number; pruned: number; accepted: number }> {
    const rows = await this.db
      .select({ token: userPushTokens.token })
      .from(userPushTokens)
      .where(eq(userPushTokens.userId, userId))
      .limit(100)

    if (rows.length === 0) {
      // Loud on purpose. A user with notificationsEnabled=true and zero tokens
      // cannot receive anything, and this path used to return in total silence.
      console.warn(`[Push] userId=${userId} has NO registered push tokens — nothing sent`)
      return { sent: 0, pruned: 0, accepted: 0 }
    }

    const messages: ExpoPushMessage[] = rows.map((r) => ({ ...message, to: r.token }))
    const tickets = await expo.sendPushNotificationsAsync(messages)

    const dead: string[] = []
    const receiptIdToToken = new Map<string, string>()

    tickets.forEach((ticket, i) => {
      if (ticket.status === 'error') {
        if (DEAD_TOKEN_ERRORS.has(ticket.details?.error ?? '')) dead.push(rows[i].token)
        return
      }
      if (ticket.id) receiptIdToToken.set(ticket.id, rows[i].token)
    })

    // Tickets are acceptance, not delivery. Poll receipts for the real outcome.
    let delivered = 0
    const ids = [...receiptIdToToken.keys()]
    for (const chunk of expo.chunkPushNotificationReceiptIds(ids)) {
      let receipts: Record<string, { status: string; details?: { error?: string } }>
      try {
        receipts = await expo.getPushNotificationReceiptsAsync(chunk)
      } catch (err) {
        // Receipts may not be ready yet. Do NOT count these as delivered.
        console.warn(`[Push] receipt fetch failed for ${chunk.length} ids:`, err)
        continue
      }
      for (const [id, receipt] of Object.entries(receipts)) {
        if (receipt.status === 'ok') { delivered++; continue }
        const error = receipt.details?.error ?? 'unknown'
        console.error(`[Push] receipt error userId=${userId} error=${error}`)
        if (DEAD_TOKEN_ERRORS.has(error)) {
          const token = receiptIdToToken.get(id)
          if (token) dead.push(token)
        }
      }
    }

    if (dead.length > 0) {
      await this.db
        .delete(userPushTokens)
        .where(and(eq(userPushTokens.userId, userId), inArray(userPushTokens.token, dead)))
    }

    console.log(
      `[Push] userId=${userId} accepted=${tickets.length} delivered=${delivered} pruned=${dead.length}`,
    )
    return { sent: delivered, pruned: dead.length, accepted: tickets.length }
  }
```

```ts
export interface ReminderPrefs {
  timezone: string | null
  reminderHour: number | null
  restDay: number | null
}

/**
 * Whether a user should receive their daily reminder at this instant.
 * Uses Intl parts rather than the toLocaleString→new Date round-trip, which
 * depends on the host locale being parseable back into a Date.
 */
export function isEligibleNow(nowUtc: Date, prefs: ReminderPrefs): boolean {
  const targetHour = prefs.reminderHour ?? 20
  let hour: number
  let weekday: number

  try {
    const parts = new Intl.DateTimeFormat('en-US', {
      timeZone: prefs.timezone ?? 'UTC',
      hour: 'numeric',
      hour12: false,
      weekday: 'short',
    }).formatToParts(nowUtc)

    hour = Number(parts.find((p) => p.type === 'hour')?.value ?? NaN)
    const wd = parts.find((p) => p.type === 'weekday')?.value ?? ''
    weekday = ['Sun', 'Mon', 'Tue', 'Wed', 'Thu', 'Fri', 'Sat'].indexOf(wd)
    if (Number.isNaN(hour) || weekday < 0) throw new Error('unparseable')
  } catch {
    hour = nowUtc.getUTCHours()
    weekday = nowUtc.getUTCDay()
  }

  // Intl renders midnight as 24 under hour12:false in some ICU versions.
  if (hour === 24) hour = 0

  if (prefs.restDay != null && weekday === prefs.restDay) return false
  return hour === targetHour
}
```

```ts
import { useCallback, useState } from 'react'
import { shouldDeepen } from '@kanji-learn/shared'
import { recordOutcome } from './cocreationApi'

export type ReinforceStep = 'scene' | 'reading' | 'self_report' | 'done'

export interface ReinforceDeps {
  record: typeof recordOutcome
}

const defaultDeps: ReinforceDeps = { record: recordOutcome }

export function useReinforce(mnemonicId: string, deps: ReinforceDeps = defaultDeps) {
  const [step, setStep] = useState<ReinforceStep>('scene')
  const [shouldOfferDeepen, setShouldOfferDeepen] = useState(false)
  const [isSubmitting, setIsSubmitting] = useState(false)

  const reveal = useCallback(() => {
    setStep((s) => (s === 'scene' ? 'reading' : s === 'reading' ? 'self_report' : s))
  }, [])

  const submitOutcome = useCallback(
    async (outcome: 0 | 1) => {
      if (isSubmitting) return          // double-tap guard
      setIsSubmitting(true)
      try {
        // The server owns the EMA (parent spec §6.1) and returns the new values,
        // so the gate is evaluated on authoritative numbers, not a local guess.
        const updated = await deps.record(mnemonicId, outcome)
        setShouldOfferDeepen(
          shouldDeepen(updated.reinforcementCount, updated.effectivenessScore),
        )
        setStep('done')
      } finally {
        setIsSubmitting(false)
      }
    },
    [deps, mnemonicId, isSubmitting],
  )

  return { step, reveal, submitOutcome, shouldOfferDeepen, isSubmitting }
}
```

```ts
import { useCallback, useState } from 'react'
import type { AssemblerSlots, CoCreationContext } from '@kanji-learn/shared'
import { deepenHook } from './cocreationApi'
import { assembleStory, type AssembledStory } from './assembleStory'

export type ThreadSource = 'environment' | 'known_knowledge'

/** The question each thread asks. Copy is additive — never "rebuild"/"replace". */
export const THREAD_PROMPTS: Record<ThreadSource, string> = {
  environment: 'Add a detail — what are you wearing, or what does the reading sound like?',
  known_knowledge:
    'What does this remind you of that you already know cold? Another kanji, a word, a memory.',
}

export interface DeepenDeps {
  deepen: typeof deepenHook
  /** The real cascade: assembleStory(slots: AssemblerSlots) => { storyText, generatedBy }. */
  assemble: (slots: AssemblerSlots) => Promise<AssembledStory>
  nowIso: () => string
}

const defaultDeps: DeepenDeps = {
  deepen: deepenHook,
  assemble: assembleStory,
  nowIso: () => new Date().toISOString(),
}

export function useDeepen(
  mnemonicId: string,
  /** The mnemonic's FULL existing context. The API validates `components` and
   *  `generatedBy` as required, so a partial object is rejected with a 400. */
  context: CoCreationContext,
  slots: AssemblerSlots,
  deps: DeepenDeps = defaultDeps,
) {
  const [thread, setThread] = useState<ThreadSource | null>(null)
  const [isSubmitting, setIsSubmitting] = useState(false)

  const chooseThread = useCallback((t: ThreadSource) => setThread(t), [])

  const submitAnswer = useCallback(
    async (answer: string) => {
      if (!thread || isSubmitting) return
      setIsSubmitting(true)
      try {
        // Feed the new answer through the same cascade the create flow uses.
        const assembled = await deps.assemble({ ...slots, anchor: answer })

        // Additive: append, never replace. Parent spec §6.3.
        const nextContext: CoCreationContext = {
          ...context,
          layers: [
            ...context.layers,
            { questions: [THREAD_PROMPTS[thread]], answers: [answer], source: thread },
          ],
          layerCount: context.layerCount + 1,
          // Record the tier that actually produced THIS layer's story.
          generatedBy: assembled.generatedBy,
          // Parent spec §8: stamp on create OR deepen. A deepened hook earns a
          // fresh quick-check — without this, deepen schedules no re-test.
          mnemonicQuizDueAt: deps.nowIso(),
        }

        await deps.deepen(mnemonicId, { storyText: assembled.storyText, context: nextContext })
      } finally {
        setIsSubmitting(false)
      }
    },
    [thread, isSubmitting, deps, context, slots, mnemonicId],
  )

  return { thread, chooseThread, submitAnswer, isSubmitting }
}
```

It becomes importable once Task 3 merges the branch.

```ts
import { selectDistractors, type DistractorKanji } from './distractors'

export interface RecallQuizItem {
  storyText: string
  choices: number[]
  correctKanjiId: number
}

/**
 * Builds a story→kanji quiz item (parent spec §8).
 * Choice order is the caller's business — shuffle at render time so the
 * correct answer is not always first.
 */
export function buildRecallQuizItem(args: {
  storyText: string
  target: DistractorKanji
  pool: DistractorKanji[]
  count?: number
}): RecallQuizItem {
  const count = args.count ?? 3
  const distractors = selectDistractors(args.target, args.pool, count)
  return {
    storyText: args.storyText,
    choices: [args.target.kanjiId, ...distractors],
    correctKanjiId: args.target.kanjiId,
  }
}
```

```ts
export function isRecallQuizDue(
  context: { mnemonicQuizDueAt?: string },
  now: Date,
): boolean {
  if (!context.mnemonicQuizDueAt) return false
  return new Date(context.mnemonicQuizDueAt).getTime() <= now.getTime()
}

/**
 * Front-loads the freshly-hooked kanji (parent spec §8: "early item while fresh").
 * At most one Buddy moment fires per session, so at most one kanji is ever
 * fresh — this adds a single tap-item, which is why it does not disturb the
 * minutes budget (design spec §7).
 */
export function insertRecallQuizFirst(queue: number[], kanjiId: number): number[] {
  return [kanjiId, ...queue.filter((id) => id !== kanjiId)]
}
```

- [ ] **Step 3: Write minimal implementation**

```ts
export const SNOOZE_DAYS = 7

export function snoozedKanjiIds(
  cards: Array<{ kanjiId: number; buddyMomentSnoozedUntil: string | null }>,
  now: Date,
): number[] {
  return cards
    .filter(
      (c) =>
        c.buddyMomentSnoozedUntil != null &&
        new Date(c.buddyMomentSnoozedUntil).getTime() > now.getTime(),
    )
    .map((c) => c.kanjiId)
}

export function snoozeUntil(now: Date): Date {
  return new Date(now.getTime() + SNOOZE_DAYS * 24 * 60 * 60 * 1000)
}
```
